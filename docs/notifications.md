# 앱 안 알림 센터

여행픽의 알림 센터는 현재 함께 여행을 편집하는 사람이 새 투표를 만들거나 직접 마감했을 때, 다른 동행이 앱 안에서 그 사실을 놓치지 않게 합니다. 1차 범위는 **투표 생성**과 **사용자에 의한 수동 마감**입니다. 알림은 일정·예약을 바꾸지 않으며, 받은 사람이 해당 여행의 투표 화면을 직접 확인하게 돕는 정보입니다.

## 사용자 흐름

1. 로그인하면 상단 알림 버튼에서 읽지 않은 개수를 확인합니다. 99개를 넘으면 `99+`로 표시합니다.
2. 알림 센터는 최근 알림부터 20개씩 보여 주고, 읽지 않은 항목에는 색뿐 아니라 `읽지 않음` 문구와 점을 함께 표시합니다.
3. 항목을 누르면 먼저 읽음으로 처리한 뒤 해당 여행의 **함께 준비 → 함께 결정하는 투표**로 이동합니다.
4. 각 항목을 따로 읽거나 현재 접근 가능한 알림을 모두 읽을 수 있습니다. 읽음 처리는 여러 번 실행해도 최초 읽은 시각을 유지합니다.
5. 상단 개수와 목록은 30초마다, 브라우저가 다시 활성화될 때 최신 상태를 확인합니다. 새로고침 주기 때문에 다른 기기의 변경이 화면에 반영되기까지 최대 약 30초가 걸릴 수 있습니다.
6. **전체 알림 / 읽지 않음** 필터로 확인할 일을 좁힙니다. 필터 변경은 1페이지부터 시작하고 필터·페이지를 주소에 보존합니다. 미확인 화면에서 읽은 항목은 빠지며, 모두 읽은 뒤에는 안내와 함께 전체 알림으로 돌아갈 수 있습니다. 개별 읽음 버튼이 사라지면 결과 영역으로 키보드 포커스를 이어 줍니다.

모바일 하단 메뉴에는 이미 메시지가 있으므로 상단의 중복 메시지 버튼은 작은 화면에서 숨기고 알림 버튼을 유지합니다. 알림은 별도 하단 메뉴를 추가하지 않아 320px에서도 기존 주요 이동 버튼이 눌리거나 잘리지 않게 합니다.

## 생성 범위

| 사건 | 수신자 | 생성하지 않는 대상 |
| --- | --- | --- |
| `TRIP_POLL_CREATED` | 저장 성공 시점의 현재 여행 참여자 | 투표를 만든 본인, 나중에 새로 참여한 회원 |
| `TRIP_POLL_CLOSED` | 수동 마감 성공 시점의 현재 여행 참여자 | 마감한 본인, 이미 종료된 요청·오래된 버전으로 실패한 요청 |

투표 생성은 질문과 모든 후보를 저장한 뒤, 수동 마감은 조건부 상태 변경이 성공한 뒤 같은 DB 트랜잭션에서 알림을 만듭니다. 알림 저장이 실패하면 원래 작업도 함께 롤백되므로 존재하지 않는 투표를 가리키는 알림이 따로 남지 않습니다. 한 수신자·투표·종류 조합의 유일 제약으로 재시도나 경합 중 중복 생성을 막습니다.

자동 마감 시각이 지난 투표는 현재 조회 시점에 `EXPIRED`로 계산할 뿐 별도 종료 작업이 실행되지 않습니다. 따라서 자동 만료 알림은 이번 범위에 포함하지 않습니다. 조회 API에 알림 쓰기 부작용을 넣지 않으며, 이후 별도 스케줄러와 중복 방지 규칙을 마련한 뒤 확장합니다.

## API 계약

모든 API는 로그인 세션을 사용하며 쓰기 요청에는 CSRF 토큰이 필요합니다. 수신자 회원 ID를 URL이나 본문으로 받지 않습니다.

### 목록과 개수

`GET /api/notifications?page=1&pageSize=20`

- `page`는 1~1,000,000, `pageSize`는 1~30입니다. 생략하면 각각 1과 20입니다.
- 선택적 `unreadOnly=true`는 DB의 `read_at IS NULL` 조건을 건수와 페이지 분할 **전에** 적용합니다. 생략하거나 `false`이면 기존 전체 조회와 같습니다. 잘못된 Boolean 입력은 400입니다. `total`·`totalPages`는 선택한 필터의 결과이며 `unreadCount`는 현재 접근 가능한 전체 미확인 개수입니다.
- 전체 개수가 줄어 현재 페이지가 마지막 페이지를 넘으면 서버가 존재하는 마지막 페이지로 보정합니다.
- 응답은 `{items,total,page,pageSize,totalPages,unreadCount}`입니다.
- 각 항목은 `id,type,readAt,createdAt,actorName,tripId,tripTitle,pollId,pollTitle`만 제공합니다.
- 행동자·수신자의 내부 회원 ID, 이메일, 다른 회원의 투표 선택은 응답하지 않습니다.

`GET /api/notifications/unread-count`는 상단 배지가 사용하는 `{unreadCount}`만 반환합니다.

### 읽음 처리

- `PUT /api/notifications/{id}/read`: 본인이 받은 현재 접근 가능한 알림 한 건을 읽음 처리하고 204를 반환합니다.
- `PUT /api/notifications/read-all`: 본인이 받은 현재 접근 가능한 미확인 알림을 모두 읽음 처리하고 204를 반환합니다.
- 이미 읽은 알림 한 건을 다시 처리해도 성공하며 최초 `readAt`을 유지합니다.
- 다른 회원의 알림 ID, 참여가 끝난 여행의 알림, 존재하지 않는 ID는 대상을 구분해 알려 주지 않고 404를 반환합니다.

## 권한과 개인정보

알림 목록·개수·읽음 SQL은 저장된 수신자뿐 아니라 **현재 `trip_members` 참여 관계를 다시 확인**합니다. 오래된 행이 예상 밖으로 남더라도 참여가 끝난 회원에게 비공개 여행·투표 제목을 보여 주지 않는 방어선입니다.

알림 테이블에는 메시지 본문, 이메일, 개별 투표 선택, 예약·결제 정보가 없습니다. 화면 문구는 현재 여행·투표·회원 정보를 조인해 만듭니다. 행동자가 탈퇴하면 회원 행의 비식별 닉네임인 `탈퇴한 회원`으로 표시됩니다.

| 사건 | 알림 처리 |
| --- | --- |
| 동행 나가기·소유자의 참여 해제 | 참여 행을 지우기 전에 대상 회원이 그 여행에서 받은 알림을 삭제 |
| 새 초대로 재참여 | 이전 알림을 복원하거나 소급 생성하지 않음 |
| 회원 탈퇴 | 탈퇴 회원이 받은 모든 알림 삭제. 다른 동행이 받은 기존 알림은 비식별 행동자 이름으로 보존 |
| 투표 삭제 | 해당 투표의 알림을 FK cascade로 삭제 |
| 여행 삭제 | 해당 여행의 투표와 알림을 FK cascade로 삭제 |

## DB 구조와 시간

V18의 공통 H2/PostgreSQL 이력과 Oracle 19c 이력은 `member_notifications`를 같은 의미로 만듭니다. `read_at IS NULL`은 읽지 않음이며, `created_at`과 `read_at`은 DB 현지 시각으로 오프셋을 별도 저장하지 않습니다. 로컬·운영 DB와 JVM 시간대는 한국 시간으로 맞춰 검증합니다.

모든 테이블·컬럼에는 역할, 상태 값, NULL 의미, 개인정보 노출 범위와 삭제 조건을 한국어 `COMMENT ON TABLE/COLUMN`으로 기록합니다. 수신자 목록·미확인 수와 `actor_id`, `trip_id`, `poll_id` 외래키 삭제 경로에는 목적에 맞는 인덱스를 둡니다.

## 현재 검증 범위

2026-10-13 최초 알림 센터 단계에서는 기본 H2와 Oracle QA 전체 **195개**, 알림 표적 HTTP 시나리오 9개, 프론트 전체 **48개**, 프로덕션 빌드·번들 예산·포맷 검사가 통과했습니다. 표적 검사는 현재 동행 fan-out, 행동자 제외, 응답 개인정보 제한, 읽음 멱등성, 페이지 보정, 참여 종료·탈퇴 정리, 투표·여행 cascade와 투표 생성/동행 제거 경합을 포함합니다.

실제 Oracle에는 V18 적용 전 `yeohaeng-pick-20261013-050024-799.dmp`를 백업한 뒤 마이그레이션했습니다. 도메인 테이블 26개·컬럼 207개, 알림 테이블·8개 컬럼 설명, 5개 명시 인덱스와 신규 알림 0건을 확인했고 재기동한 웹/API는 모두 200입니다. 프론트는 401·403·404 때 캐시된 비공개 목록과 배지를 제거하도록 보강했습니다. 격리 메모리 H2의 합성 계정으로 320px·390px 가로 넘침 0, 버튼 44px 이상, 개별/전체 읽음과 배지 갱신, 투표 영역 이동·포커스, 콘솔 오류 0건을 확인했습니다.

2026-10-13 미확인 필터 보강에서는 H2 전체 196개와 알림 HTTP 10개를 H2·Oracle QA에서 각각 통과했고 프론트 50개·빌드·번들 예산·포맷 검사를 통과했습니다. 격리 합성 계정의 320px·390px에서 가로 넘침 0, 필터 45px·개별 읽음 44px, 버튼 글자 14px 이상을 확인했습니다. 필터 주소 유지·새로고침·개별/전체 읽음·전체 목록 복귀도 실제 브라우저에서 확인했습니다. V18 구조와 DB 의미는 유지하므로 새 마이그레이션은 없습니다.

## 후속 범위

초대 수신·응답, 개인/단체 메시지, 예약·일정 변경, 자동 투표 만료, 이메일·브라우저 푸시와 알림별 수신 설정은 후속입니다. 메시지 알림을 추가할 때도 본문을 알림 테이블에 복제하지 않고 기존 대화 권한·차단·참여 종료 트랜잭션 안에서 생성해야 합니다. 공개 운영 전에는 알림 보존 기간과 정리 작업을 개인정보 처리방침과 함께 확정합니다.
