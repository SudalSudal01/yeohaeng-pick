# 회원 탈퇴

마이페이지의 별도 `계정 관리` 카드에서 안내를 열고, 현재 비밀번호와 삭제·보존 확인 체크를 입력해 실행한다. 소유한 여행이 하나라도 있으면 실행 양식 대신 여행별 이동 링크를 보여준다. 수락한 동행에게 소유권을 넘기거나 여행을 직접 삭제한 다음 탈퇴할 수 있다. 혼자 소유한 여행도 예외가 아니다.

## 계약과 처리 순서

- `GET /api/auth/withdrawal`: 로그인 회원의 `{ownedTrips:[{id,title,memberCount}],joinedTripCount}`. 비밀번호·예약·다른 회원 이메일은 포함하지 않는다.
- `DELETE /api/auth/account`: `{password,confirmed:true}`. 대상 ID는 받지 않으며 현재 로그인한 회원만 처리한다. 로그인·CSRF·입력·현재 BCrypt 비밀번호를 검사한다. 성공은 204다.
- 비로그인은 401, 잘못된 확인 입력은 400, 비밀번호/CSRF 실패는 403, 남은 소유 여행은 409다. 실행 직전 소유권을 다시 조회하므로 사전 화면이 오래돼도 소유 여행을 방치하지 않는다.
- 탈퇴의 비밀번호 시도는 IP 기준 분당 10회이며 초과는 429와 Retry-After다. 기존 로그인/메일 제한과 마찬가지로 단일 프로세스용이다.
- 관련 여행을 ID 순서로 잠근 뒤 소유 여부를 확인한다. 참여 여행의 version을 올려 오래된 비교를 거절하고, 참여 연결·초대·차단·메일 토큰을 정리한다. 개인 대화 종료, 공개 작성물 본문 제거와 계정 비식별화를 한 DB 트랜잭션으로 커밋한다.
- 커밋 후 현재 세션/쿠키를 종료한다. 다른 기기의 세션은 deleted_at 또는 credential_version 불일치로 다음 요청부터 401이다. 원래 이메일로 재가입할 수 있지만 새 ID를 발급하며 예전 기록과 연결하지 않는다.

## 삭제·보존 범위

| 대상 | 처리 |
| --- | --- |
| 이메일·비밀번호 해시·닉네임·취향·수신 설정·인증 여부·관리자 역할 | 원래 값을 제거. 로그인이 불가능한 내부 식별값, `탈퇴한 회원`, 빈 취향, 수신 OFF, USER 역할로 전환 |
| 회원 행 | 공동 기록의 FK를 위해 ID·가입/탈퇴 시각·인증 버전만 포함한 비식별 행 유지. 삭제된 계정은 로그인·인증·재설정·초대·개인 대화 대상에서 제외 |
| 작성한 글·댓글 | 휴지통 본문까지 제거. 게시글 제목/지역/모집 조건 제거·모집 종료·삭제 상태 유지. 공개 목록/상세에서 제외. ID는 댓글/신고 연결을 위해 보존 |
| 다른 회원의 댓글 | 삭제하지 않음. 탈퇴자의 글 아래 댓글은 부모 글이 공개되지 않아 함께 비공개 |
| 여행 참여·발신/수신 초대·양방향 차단·메일 토큰 | 삭제 |
| 공개 일정 가져오기 완료 기록 | 본인 요청 키/해시/복사본 연결 삭제. 다른 회원이 만든 독립 복사본과 그 기록은 보존 |
| 참여 여행의 일정·예약·준비물·경비·소유권/방문 이력·계획 인원·취향·공개 링크 | 보존. 계정 참여 수와 계획 인원은 다른 값이므로 인원/금액을 자동 수정하지 않음 |
| 단체 대화 | 현재 참여 권한 회수. 다른 동행의 방과 메시지는 보존 |
| 개인 대화 | 기존 수락/대기 방 모두 CLOSED로 전환. 상대방은 기존 메시지 조회·신고만 가능, 새 발송·수락/재개·새 요청 불가 |
| 남는 공동 기록/대화의 작성자 이름 | 회원 조인으로 현재 비식별 닉네임 `탈퇴한 회원` 표시 |
| 신고 사유·처리 결과·운영 감사 | 운영 증거로 보존. V13 이후 신고한 글/메시지는 당시 닉네임·본문도 별도 유지. 기존 신고는 소급 생성하지 않음. [필드/한계](report-evidence.md) |

보존되는 자유 입력 기록에 직접 적은 개인정보를 자동 탐지/삭제하지 않는다. 외부 예약·결제의 취소/환불과는 무관하다. 위 내용은 현재 기능의 처리 범위이며 법적 보존 기한·운영 개인정보 처리방침·개별 삭제 요청 정책은 별도 확정해야 한다.

## 경합 경계와 운영 한계

`AccountLifecycle`은 단일 JVM의 공정한 read/write 잠금이다. 로그인한 일반 요청은 공유 잠금으로 병렬 실행하고, 탈퇴만 배타 잠금을 얻어 진행 중인 모든 로그인 요청이 끝나기를 기다린다. 익명 로그인/가입/메일도 공유 경계를 사용하며, 토큰 소비 잠금은 트랜잭션 완료까지 유지한다. 계정별 잠금을 여러 대상에 중첩하는 교착 문제와 요청 완료 후 본문/초대가 되살아나는 문제를 피한다. 여행 자체의 DB 행 잠금·version 검사는 계속 사용한다.

탈퇴 중에는 같은 서버의 다른 로그인 요청도 잠시 대기하며, 느린 외부 조회/SMTP 요청이 먼저 실행 중이면 탈퇴가 기다릴 수 있다. 여러 JVM에서는 이 잠금을 공유하지 않으므로 **다중 서버 배포 전에 DB/분산 잠금과 분산 세션으로 교체해야 한다**. 운영 PostgreSQL의 잠금 동작은 아직 검증하지 않았다. 현재 규모의 로컬 단일 서버에서 검증한 설계다.

탈퇴 복원·가입 이메일 보관·계정 영구 물리 삭제·메시지 개별 삭제 UI·보존 기한별 정리 작업·백업 내 이전 개인정보 제거는 포함하지 않는다. 개발 백업은 자동 삭제되지 않으므로 운영 전 접근/암호화/보관 기한/복구 후 삭제 재반영 정책이 필요하다. 다른 브라우저에 이미 다운로드된 데이터까지 지울 수 없으며 기존 폴링/다음 요청에서 권한 종료가 반영된다.
