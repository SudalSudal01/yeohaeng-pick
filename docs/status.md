## 권장 후속 순서

사용자 요청에 따라 새 기능보다 기존 UI의 가독성을 우선합니다. 공통 기준은 `AGENTS.md`와 스타일 토큰에 기록했으며 이후 화면에도 같은 기준을 적용합니다.

1. 실제 검색 결과의 여행 분류·지역 범위를 정교하게 하고 다양한 기간·취향의 추천 품질과 모바일 UX를 확인한다. 연결한 SMTP의 비밀번호 재설정 흐름도 확인한다.
2. 교통 예약 보호, 날짜 간 경로 반영, 역 연결, 숙소 경유·최소 체류, 숙박 조건과 저장 후 숙소 변경 비교를 구현했다. 전체 일정은 장소·날짜·순서를 유지하는 양방향 방문 시간 조정으로 확장했다. 이후 장소 운영시간을 구조화하고 날짜별 시작/마감, 방문 순서 재탐색과 더 다양한 대안을 보강한다. 반영한 구간은 조회 기록, 나머지는 거리 추정이며 역 연결 계산은 읽기 전용이다. 지역 간 항공·선박과 날짜별 운행/좌석은 별도 공급자 검토가 필요하다.
3. TourAPI 원문 조회와 사용자가 직접 입력하는 당일 방문 가능 시간·예상 비용을 연결했다. 전체 시간 조정은 가능 범위 안에서 배치하고, 다른 시간 변경 비교·복원도 충돌을 검사한다. 이후 전국 후보·행사·체험 분류와 복수 이용 구간을 보강한다. 원문만으로 영업 여부나 확정 요금을 추측하지 않는다.
4. 일반 후보와 본인 찜을 저장 후 숙소 비교와 방문 장소 비교에 연결했다. 방문 찜은 한 곳만 현재 정보로 다시 확인하며 동행 각자의 개인 목록은 공유하지 않는다. 이후 날짜별 숙소·조건별 대안으로 확장하고, 객실 정원·재고·실제 이용 정책은 공급자 확인이 가능한 범위에서 확장한다. 현재 숙소는 지역별 한 곳이다.
5. 동행 나가기/참여 해제와 접근 회수, 소유권 이전, 내 글/댓글 관리와 회원 탈퇴를 연결했다. 신고 당시 내용 보존, 커뮤니티 서버 검색·페이지 이동과 여행 공동 투표를 추가했다. 이후 투표 생성·마감 알림, 다른 긴 목록의 페이지 이동, 소셜 로그인과 운영 보존/백업 정책을 완료한다.
6. 로컬 Oracle 전환과 격리 HTTP 검증을 완료했다. 로컬 Data Pump 백업을 추가했다. 이후 Oracle 복구 훈련·운영 백업/환경 분리, 메일 수신·발송 한도, HTTPS·관측·분산 세션과 한도를 검증한다.
7. 제휴가 확보된 공급자에 한해 예약 콜백/재고/가격을 연동한다. 이 시점 전에는 PARTNER_CONFIRMED를 사용자 입력으로 허용하지 않는다.

무료 우선 원칙은 실제 공급자의 할당량과 운영비를 확인하며 지킵니다. 현재 메모리 호출 제한은 단일 프로세스용이며 서버 재시작/다중 인스턴스에 걸친 과금 방지 장치가 아닙니다.
