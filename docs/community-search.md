# 커뮤니티 검색과 페이지 이동

공개 목록은 최근 100개를 받아 화면에서 분류하던 방식에서, 서버가 전체 공개 글을 조건별로 조회하는 방식으로 변경했습니다. 기존 테이블·컬럼의 의미와 DB 코멘트는 그대로 사용하므로 새 마이그레이션은 없습니다.

## HTTP 계약

`GET /api/community/posts`는 로그인 없이 읽을 수 있습니다. **기존 배열 응답을 페이지 객체로 변경**했으며 앱의 목록과 관련 테스트를 함께 갱신했습니다. 상세·작성·수정·휴지통 API는 기존 계약을 사용합니다.

| 매개변수 | 기본값·범위 | 의미 |
| --- | --- | --- |
| `q` | 빈 문자열, 최대 100자 | 제목 또는 본문 전체의 부분 문자열. 영문 대소문자를 구분하지 않으며 `%`, `_`, `!`도 입력한 문자로 검색 |
| `region` | 빈 문자열, 최대 50자 | 글에 기록된 지역명의 부분 문자열. 위치 좌표·행정구역 자동 추론 없음 |
| `category` | 빈 문자열 | 전체 또는 `후기`, `추천`, `코스`, `동행`, `의견` |
| `status` | 빈 문자열 | 동행 종류에서만 `OPEN`, `CLOSED`, `CANCELLED`. 비동행 종류와 함께 보내면 400 |
| `page` | 1, 1~1,000,000 | 1부터 시작. 현재 범위를 벗어나면 마지막 페이지로 보정 |
| `pageSize` | 12, 1~30 | 한 페이지 최대 글 수. 웹 화면은 12개로 고정 |

조건은 AND로 결합하며 앞뒤 공백은 제거합니다. 검색어는 단어별 분리·유사어·초성 검색 없이 입력한 문자열을 연속해서 찾습니다. 길이·형식·선택 값이 잘못되면 400을 반환합니다.

응답은 `{items, total, page, pageSize, totalPages}`입니다. 결과가 없으면 `items=[]`, `total=0`, `page=1`, `totalPages=0`입니다. `items`는 `id`, `category`, `region`, `title`, `excerpt`, `nickname`, `createdAt`, `recruitmentDate`, `capacity`, `status`만 포함합니다. 본문 전체·작성자 계정 ID·이메일·버전·삭제/숨김 정보·댓글은 목록에 포함하지 않습니다. 날짜는 `YYYY-MM-DD` 달력 날짜이며 미리보기는 본문의 첫 약 280자입니다. 부분 문자열 경계에서 잘린 이모지의 반쪽은 응답에서 제거합니다.

## 조회와 공개 범위

`CommunitySearchService`가 입력 규칙·페이지 보정을, `CommunitySearchMapper/Sql`이 건수와 제한된 목록을 담당합니다. 두 SQL은 같은 필터를 재사용합니다. SQL 구조에 사용자 문자열을 결합하지 않고 값과 OFFSET/개수를 바인딩합니다. 공개 목록과 건수 모두 운영진 숨김 및 작성자 삭제 글을 제외합니다.

본문 CLOB는 `LOWER/LIKE`로 **전체** 검색하고, 응답 미리보기에만 `SUBSTR`를 사용합니다. 4KB 이후의 본문도 검색합니다. Oracle의 지원 범위는 [Oracle 19c SQL semantics and LOBs](https://docs.oracle.com/en/database/oracle/oracle-database/19/adlob/SQL-semantics-and-LOBs.html)의 CLOB 함수 표를 참고했습니다. H2와 Oracle에서 같은 실제 HTTP 시나리오를 검증합니다.

정렬은 `created_at DESC, id DESC`입니다. 작성 시각이 같은 글도 데이터 변경이 없다면 페이지가 중복되지 않습니다. 건수와 목록은 읽기 전용 트랜잭션에서 별도 조회하며 글쓰기·삭제를 잠그지 않습니다. 동시 등록/삭제 중에는 건수와 화면 구성이 일시적으로 바뀔 수 있으며 장시간 고정된 검색 스냅샷은 제공하지 않습니다. 현재는 부분 문자열 검색이므로 글이 많아지면 실행 계획·부하를 측정하고 전문 검색 또는 커서 방식 도입을 검토해야 합니다.

## 화면과 돌아가기

검색어·지역·동행 모집 상태는 버튼 또는 Enter로 적용합니다. 이야기 종류는 바로 적용하며 다른 종류로 바꾸면 모집 상태를 해제합니다. 조건 변경은 첫 페이지로 돌아갑니다. 초기화는 전체 목록으로 돌아갑니다.

적용한 조건과 페이지를 URL 및 React Query 키에 저장합니다. 상세 링크의 `returnTo`는 커뮤니티 목록 주소만 허용하며 새로고침, 브라우저 뒤로/앞으로, 상세의 커뮤니티 링크, 작성자 삭제 후 복귀에서도 조건을 보존합니다. 서버가 마지막 페이지를 보정하면 URL도 교체합니다. 페이지 버튼으로 이동했을 때만 결과 시작으로 포커스를 옮기며 15초 자동 갱신에서는 스크롤/포커스를 옮기지 않습니다.

검색 안내 14px·입력 16px·버튼 높이 48px, 안내와 실행 간격 24px를 적용했습니다. 좁은 화면에서는 입력과 페이지 정보를 세로로 배치합니다. 로딩·실패/재시도·검색 결과 없음·전체 글 없음·조건 초기화를 구분합니다.
