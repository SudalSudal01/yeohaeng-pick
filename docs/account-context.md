# 계정 변경과 비공개 화면의 경계

같은 브라우저의 여러 탭, 지연 응답, 로그인 성공 뒤 본문만 유실되는 경우에도 이전 회원의 초안과 자료를 다음 회원에게 붙이지 않는다.

## 서버의 판단

- 로그인은 기존 세션을 종료하고 새 세션 객체를 만든다. 진행 중인 A 요청과 새 B 로그인이 세션 속성/종료를 공유하지 않는다.
- 인증·비밀번호 재설정은 회원 행 → 토큰 순서로 잠그고, 잠금을 기다린 뒤 만료·소비 여부를 다시 검사한다. 다른 유효 링크 두 개가 동시에 비밀번호를 바꾸어도 하나만 성공한다.
- 비밀번호 재설정은 토큰 소유자의 인증 버전을 변경한다. 로그인한 다른 회원이 그 링크를 사용해도 관계없는 현재 세션을 종료하지 않는다.
- `X-Travel-Member`가 있으면 실제 인증 주체와 대조한다. 다른 회원이면 `409`, `X-Travel-Account-Changed: true`, `code: ACCOUNT_CHANGED`로 업무 처리를 시작하지 않는다. 실제 회원 ID는 오류에 넣지 않는다.
- 이 헤더는 인증 수단이 아니다. 없거나 임의로 넣어도 서버 세션·CSRF·객체 권한이 필요하다. 기존 클라이언트 호환은 유지하며 새 웹의 요청 문맥 보호와 구분한다.

## 화면의 판단

로그인·로그아웃·재설정·탈퇴는 하나의 전환 경계를 사용한다. 같은 페이지는 중복 요청을 거절하고, 지원하는 HTTPS/localhost 브라우저에서는 Web Locks로 다른 탭의 쿠키 변경도 직렬화한다. 시작/완료를 BroadcastChannel의 임의 표시만으로 알리며 회원 ID·메일·비밀번호·CSRF를 전달하지 않는다. 완료 신호가 유실되면 45초 후 서버의 현재 쿠키를 다시 확인한다.

다른 탭은 요청 세대를 종료하고 비공개 Query·Mutation과 `me` 내용을 정리한다. `me` Query 객체는 유지해 기존 관찰자도 즉시 빈 상태와 새 회원을 받는다. 새 회원은 `/auth/me`로 확인하며 이 확인 자체에는 이전 기대 회원 헤더를 보내지 않는다. 활성화/재연결 때도 확인한다.

보호 화면은 회원 ID로 구분해 다시 만든다. 서버가 B를 확인한 뒤 A의 메시지 초안·모달·선택 상태를 재사용하지 않는다. 기대 회원은 React에 커밋된 화면의 회원과 동기화한다. CSRF 대기 전 요청 문맥을 캡처하고, 문맥이 끝나면 옛 입력을 새 쿠키로 보내지 않는다. 미확인 문맥의 비공개 변경은 전송 전에 거절한다.

탈퇴의 주체는 모달을 연 회원으로 고정한다. 현재 계정이 다르면 제출하지 않으며, 전송에도 고정한 주체를 명시한다. 본인 탈퇴 완료는 현재 계정/실제 경로를 확인해 안내하고, 이미 떠난 화면이나 다른 회원의 화면은 늦은 응답으로 이동시키지 않는다. 이전 `RequireAuth`도 새 공개 완료 경로를 로그인 화면으로 덮지 않는다.

## 실패와 회복

- CSRF 발급은 동시 요청 사이에 한 번만 수행한다. 보안 토큰 거절 후에는 다음 수동 시도에서 다시 발급한다.
- 시간 제한은 CSRF 10초, 보통 요청 30초, 추천/교통 90초이며 응답 본문 완료까지 포함한다. 변경 요청을 자동 재전송하지 않는다.
- 현재 문맥의 401은 본문이 멈춰도 헤더에서 즉시 정리한다. 이전 401/계정 변경 응답은 새 로그인을 종료하지 않는다.
- Set-Cookie는 본문보다 먼저 적용될 수 있으므로, 인증 전환 시작과 불확정 결과에서 이전 개인 캐시를 유지하지 않는다. 새 로그인 응답을 확인하기 전까지 이전 회원을 재표시하지 않는다.
- 조회 실패, 정상 빈 목록, 접근 종료를 구분한다. 신고·휴지통과 알림의 개별 범위는 [사회 기능 계약](social-stability.md), 메시지는 [메시지 계약](messaging.md)을 따른다.

검증에는 합성 계정만 사용한다. 실제 HTTP에서 기대 회원 불일치·새 세션 객체·토큰 경합을 확인하고, 브라우저에서 BC 지원/미지원·쿠키만 변경·본문 유실·지연 탈퇴·로컬 초안 소거를 재현한다. 전체 결과는 [검증 기록](verification.md)에 날짜별로 남긴다.
