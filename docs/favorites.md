# 개인 찜과 여행 추천 연결

장소 탐색에서 찜한 장소·숙소를 본인 계정에 최대 200곳 보관합니다. `/favorites`와 마이페이지에서 지역/분류 필터, 12개 단위 페이지 이동, 지도/리뷰 링크를 제공합니다. 방문 찜은 코스에서 우선 고려하고, 숙소 찜은 다시 확인한 뒤 여행 동선의 기준으로 선택합니다.

## 신뢰와 개인정보

- 회원 ID는 로그인 세션으로 결정하고 조회·삭제 SQL에 본인 조건을 바인딩합니다. 동행, 공개 일정, 커뮤니티에 전체 목록이나 개인 찜 상태를 제공하지 않습니다.
- 저장 입력은 장소 ID와 검색 조건입니다. 서버가 같은 검색을 실행해 확인한 이름·좌표·금액·URL만 보관합니다. 클라이언트 장소 메타데이터는 신뢰하지 않습니다.
- 회원 행 잠금과 복합키로 중복/해제 및 200개 상한 경쟁을 보호합니다. 재저장은 최초 저장일/정보를 유지하며 이미 해제한 장소의 삭제도 성공합니다.
- 보관 목록은 당시 정보이며 예약/결제/영업 상태가 아닙니다. 탈퇴 시 삭제합니다. 찜 해제는 이미 저장한 여행의 방문 장소나 숙소를 삭제하지 않습니다.

## 방문 장소 선택

여행 만들기 취향 단계에서 해당 지역의 방문 찜을 최대 5곳 선택합니다. 찜 목록의 **이 장소 우선 고려하기**는 지역과 초기 선택을 전달합니다. 현재 장소를 AI 후보에 합치고 엔진이 우선 평가하지만 강제 방문/예약 고정은 아닙니다. 분류 균형과 이동·시간 제약으로 빠질 수 있어 코스별 반영 개수와 빠진 이름을 표시합니다. 코스 다양화를 위한 대체 과정에서는 선택된 찜을 제거하지 않습니다.

## 숙소 찜 선택

찜 목록의 **이 숙소 확인하고 여행 만들기**는 지역과 확인할 숙소를 전달합니다. 자동 선택하지 않고 숙소 단계에서 해당 카드를 먼저 보여 줍니다.

1. **현재 정보 확인**으로 필요한 한 곳만 재조회합니다. 전체 찜을 자동으로 공급자에게 조회하지 않습니다.
2. 보관 당시 정보와 다시 확인한 장소·출처·조회 시각을 구분합니다. 장소 조회는 최대 5분 전 캐시일 수 있으며 Kakao 객실 요금/재고는 예약처에서 확인해야 합니다.
3. **동선 기준으로 선택**을 별도로 눌러 적용합니다. 지역별 한 숙소를 유지하고 같은 지역의 다른 후보로 바꾸면 이전 숙소와 개인 찜 선택 표시를 정리합니다. 다른 지역 선택은 유지합니다. 접힌 목록에서도 링크의 숙소와 현재 선택은 보여 줍니다.
4. 세 코스에 기준 숙소 이름/내 찜 표시를 제공합니다. 숙소는 방문 장소로 삽입하지 않습니다. 저장된 숙소 예약 상태는 `NONE`으로 시작합니다.

`POST /favorites/lodgings/resolve`는 로그인/CSRF를 요구합니다. 입력 `{placeId,region}`, 응답 `{place,checkedAt}`이며 확인 시각은 객실 요금/재고 확인 시각이 아닙니다. 새 여행의 `favoriteLodgingIds`는 `lodgingIds`의 부분집합, 최대 5개, 중복 없이 지역별 한 곳입니다. 생략하면 기존 일반 후보 선택 계약을 유지합니다.

## 추천과 저장 재검사

양쪽에서 본인 찜·중복·개수·지역·방문/숙소 분류를 검사합니다. 보관한 이름/지역으로 재검색해 동일 공급자 ID만 사용하고 일반 검색 첫 결과 밖의 숙소도 검증된 개인 찜이면 합칩니다. 잘못된 선택은 400, 해제/검색 누락/현재 분류 변경은 409, 공급자 실패는 503입니다. 과거 정보나 예시 데이터로 대체하지 않습니다. 확인 후 찜을 해제하면 추천/저장에서도 거절합니다.

찜/일반 후보의 화면 조회는 별도로 실패를 표시하지만 추천/저장은 필요한 전체 후보 조회가 성공해야 진행합니다. 지역 변경 시 숙소/방문 찜 선택을 초기화하며 미리 안내합니다. 재조회 실패 후 이전 성공 정보로 새 선택하지 않고 기존 선택 해제만 허용합니다.

개인 찜 선택 ID는 여행/공유 응답에 보관하지 않습니다. 저장된 방문/숙소는 일반 여행 장소로 독립 유지됩니다. 공개 일정 가져오기는 새 개인 숙소 찜 삽입을 허용하지 않습니다.

## 저장한 여행의 숙소 비교

여행 상세의 **숙소 비교 → 내 찜 숙소**에서 숙박 지역을 고르고, **현재 정보 확인 → 이 숙소 비교하기 → 변경 적용**을 순서대로 진행합니다. 현재 기준 숙소는 제외합니다. 개인 찜 전체 목록은 동행에게 공개하지 않고, 적용한 숙소만 공동 일정의 일반 숙소로 보입니다.

숙소 비교/적용 요청의 선택적 `favorite: true`는 본인의 찜을 다시 조회하도록 지정합니다. 일반 검색어와 함께 사용할 수 없으며 이름·좌표·금액을 입력받지 않습니다. 비교와 적용에서 각각 소속·버전·숙박 지역·본인 찜·현재 공급자 정보를 검사합니다. 일반 후보 밖의 숙소도 검증된 본인 찜이면 비교할 수 있습니다. 찜 해제/조회 누락은 409, 공급자 실패는 503이며 저장된 숙소와 일정은 유지합니다.

기존 예약 완료 숙소 보호, 동시 편집 충돌, 관련 반영 경로 해제와 숙박 조건 초기화를 그대로 적용합니다. 비교만으로 일정이 바뀌지 않고 방문 장소·방문 시각은 유지합니다. `favorite` 생략/false는 기존 일반 후보 비교 계약입니다. 찜 목록 출처는 여행·공유에 저장하지 않습니다.

## DB와 후속 범위

기존 V15 `favorite_places`의 회원/장소 복합키, 서버 장소 JSON CLOB, 최초 DB 저장 시각을 사용합니다. Oracle/공통의 한국어 코멘트를 유지하며 이번 숙소 연결에는 스키마 변경이 없습니다. 예약·대화·출발지·결제 개인정보는 찜에 보관하지 않습니다.

찜 공유/투표, 저장한 여행에서 찜 방문 장소 선택, 강제 방문/방문 순서 재탐색, 대규모 서버 페이지 이동은 후속입니다. 숙소 찜 선택은 요금·재고·예약·결제 완료를 보장하지 않습니다.
