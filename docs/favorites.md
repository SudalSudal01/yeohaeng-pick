# 개인 찜과 추천 연결

장소 탐색의 **찜하기**로 본인 계정에 보관하고 `/favorites` 또는 마이페이지에서 다시 봅니다. 장소·숙소를 최대 200곳 보관하며 지역/분류 필터, 12개 단위 페이지 이동, 지도/리뷰 링크를 제공합니다. 현재 숙소 찜은 다시 찾아보는 용도입니다. 숙소 동선 기준은 기존 숙소 선택 단계에서 별도로 정합니다.

## 신뢰와 개인정보

- 회원 ID는 요청에서 받지 않고 로그인 세션으로 결정합니다. 조회·삭제 SQL은 항상 본인 조건을 바인딩합니다. 동행, 공개 일정, 커뮤니티에 찜 상태나 전체 목록을 제공하지 않습니다.
- 저장 입력은 장소 ID와 검색 조건뿐입니다. 같은 검색을 서버에서 실행해 ID가 있는 경우에만 서버의 이름·좌표·금액·URL을 JSON으로 저장합니다. 클라이언트가 보낸 장소 메타데이터를 신뢰하지 않습니다.
- 회원 행 잠금과 복합 기본키로 중복 저장/해제 및 200개 상한 경쟁을 보호합니다. 같은 장소 재저장은 최초 저장일/스냅샷을 유지하며, 이미 해제한 장소의 삭제도 성공합니다.
- 보관 목록은 당시 정보입니다. 비용은 참고 활동비이며 예약/결제/현재 영업 상태가 아닙니다. 탈퇴 시 개인 찜은 삭제합니다. 찜을 해제해도 이미 저장한 여행의 방문 장소는 삭제하지 않습니다.

## 이번 여행에 선택하기

여행 만들기의 취향 단계에서 해당 여행 지역의 찜한 **방문 장소**를 최대 5곳 선택합니다. 찜 목록의 **이 장소 우선 고려하기**는 지역과 초기 선택을 새 여행 입력에 전달합니다. 지역을 변경하면 숙소/찜 선택을 초기화하며 화면에서 미리 안내합니다.

서버는 추천과 여행 저장 양쪽에서 본인 찜 여부·중복·개수·여행 지역·방문 분류를 검사하고, 보관한 이름/지역으로 현재 장소를 다시 검색해 동일 공급자 ID만 사용합니다. 기존 검색 캐시(최대 5분)를 사용할 수 있습니다. 찾지 못하거나 이미 해제한 찜은 409, 공급자 조회 실패는 503이며 과거 스냅샷이나 예시 장소로 대체하지 않습니다.

현재 장소를 AI 후보에 합친 뒤 일정 엔진이 찜을 우선 평가합니다. 강제 방문/예약 고정은 아니며 분류 균형과 이동·시간 제약으로 빠질 수 있습니다. 코스별 반영 개수와 빠진 장소 이름을 모두 표시합니다. 코스 차이를 만들기 위한 대체 과정에서는 선택된 찜을 제거하지 않습니다. 선택 ID는 여행/공유 응답에 보관하지 않으며, 저장된 방문 장소는 기존 여행의 일반 장소로 독립 유지됩니다.

## DB

V15 `favorite_places`: `member_id`, `place_id` 복합키, 서버 장소 JSON CLOB, 최초 DB 저장 시각. Oracle/공통 마이그레이션에 동일한 한국어 테이블·컬럼 코멘트를 추가합니다. 예약·대화·출발지·결제 개인정보는 보관하지 않습니다.

## 후속 범위

찜은 현재 본인 전용이며 동행에게 공유/투표하거나 이미 저장한 여행에 자동 삽입하지 않습니다. 숙소 찜의 선택 단계 직접 연결, 강제 방문 조건과 방문 순서 재탐색, 대규모 서버 페이지 이동은 후속입니다.
