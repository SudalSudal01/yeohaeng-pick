# 신고 당시 내용과 관리자 처리

신고는 접수 순간의 대상 한 건을 복사합니다. 이후 원문 수정·휴지통 이동·회원 탈퇴가 운영 확인 자료를 덮어쓰지 않습니다. 신고하기 화면에서도 보존 범위를 안내합니다.

| 대상 | 보존하는 정보 | 보존하지 않는 정보 |
| --- | --- | --- |
| 게시글 POST | 글 ID, 작성자 ID/당시 닉네임, 종류·지역·제목·본문·버전·작성/수정 시각 | 댓글, 계정 이메일·비밀번호·취향, 예약·여행 |
| 메시지 MESSAGE | 메시지 ID, 발신자 ID/당시 닉네임, 본문 한 건·작성 시각 | 다른 메시지, 대화방 전체, 상대방 이메일 |
| 회원 USER | 회원 ID·당시 공개 닉네임 | 이메일·권한·비밀번호·취향·대화 |

게시글은 수정·삭제·숨김과 같은 행을 잠그고 공개 여부를 확인한 뒤 복사합니다. 메시지는 현재 대화 접근 권한을 검사합니다. 회원은 활동 계정의 공개 필드만 조회합니다. 없는 대상·숨긴/삭제한 글은 404, 다른 사람의 개인 대화는 403입니다. 비로그인·CSRF 누락은 기존 보안 규칙을 적용합니다.

`ReportService`가 JSON 화이트리스트와 트랜잭션을 담당하고 `ReportMapper`는 접수 시에만 `evidence`를 씁니다. Oracle에서는 CLOB를 전용 `LongTextTypeHandler`의 `setClob(Reader)`로 바인딩하여 한글/이모지 청크 경계를 보존합니다. 적용된 V1~V11은 변경하지 않았고 V12는 DB 코멘트, V13은 증거/보존 시각/처리 시각/관리자 ID만 추가합니다.

이전 신고의 `evidence`와 `captured_at`은 NULL입니다. 현재 내용을 소급 복사하지 않으며 관리자에게 미보존 안내를 표시합니다. 이전 처리 결과도 유지하고 없는 처리 시각/관리자를 만들어 넣지 않습니다.

## 처리와 화면

관리자만 최근 100개 신고를 읽을 수 있습니다. 신고 사유, 접수 당시 내용, 보존 시각, 처리 입력을 구분합니다. 긴 본문은 접기/펼치기와 내부 스크롤을 제공하고 HTML로 실행하지 않습니다. 본문 15px·안내 14px·입력 16px·버튼 48px, 안내 아래 실행 여백 24px을 유지합니다.

처리 사유는 1~1,000자입니다. 게시글은 **현재 게시글도 숨기기**를 별도로 선택하며 기본값은 해제입니다. 숨김은 삭제된 글을 복원하지 않습니다. 메시지/회원 신고에서 게시글 숨김을 요청하면 400입니다.

신고 행 잠금 → OPEN 검사 → 선택한 게시글 숨김 → RESOLVED/사유/처리 시각/관리자 저장 → 감사 요약을 하나의 트랜잭션에서 수행합니다. 두 관리자가 동시에 처리해도 최초 요청만 성공하고 나머지는 409입니다. 완료 기록을 다시 수정하는 API는 없습니다. 상세 사유는 reports에 보관하고 admin_audit의 200자 요약에는 긴 사유/개인 대화 본문을 중복 삽입하지 않습니다.

화면은 공백 사유와 중복 클릭을 막고 저장 실패를 안내합니다. 다른 창에서 먼저 처리되면 오류 알림과 최신 완료 결과를 보여줍니다. 운영진 숨김 때문에 글 버전이 증가하면 기존 작성자의 오래된 수정 요청도 충돌합니다.

## 보존의 현재 한계

현재 자동 파기 기한·별도 개인정보 삭제 요청·법정 보존 정책은 구현하지 않았습니다. 공개 운영 전에 보존 기간, 접근 감사, 백업의 보존/파기·복구 절차를 정해야 합니다. 회원 탈퇴 후에도 신고 증거에 당시 닉네임/본문이 남을 수 있으며 이를 계정 비식별화와 같은 의미로 설명하지 않습니다. 기존 일반 대화의 보존 정책도 별도입니다. 조회는 최근 100건으로 제한하며 검색·페이지네이션·처리 후 재심 기능은 후속입니다.

## 검증

`ReportFlowTest`는 같은 실제 HTTP 시나리오를 H2/Oracle QA에서 실행합니다. 원문 수정·삭제·탈퇴 후 증거 불변, 긴 한글/이모지, 메시지 한 건만 공개, 다른 대화 접근 거절, 회원 필드 최소화, 대상/입력/세션/CSRF/관리자 검사, 명시적 숨김, 1,000자 사유, 중복/동시 처리의 단일 감사 기록을 확인합니다. 별도 V11 H2의 기존 신고를 V13으로 올려 사유/결과 보존과 NULL 증거를 검사하고 실제 DB 사전에서 모든 도메인 테이블/컬럼의 코멘트 누락이 없는지도 검사합니다.
