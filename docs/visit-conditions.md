# 직접 확인한 방문 조건

저장된 여행의 각 장소에서 **방문 조건 설정**을 엽니다. 관광공사 이용정보에서 장소·주소와 운영 안내를 확인한 뒤 **확인 후 방문 조건 설정**으로 이동할 수도 있습니다. 공급자 원문은 자동 변환하거나 복사하지 않습니다.

입력은 해당 방문일의 단일 연속 가능 시간, 선택적 1인당 예상 비용과 확인 메모입니다. 가능 시간은 06:00~22:00 안에서 체류 전체를 마칠 수 있어야 합니다. 요일·계절·임시 휴무·입장 마감·휴게 시간은 여행 날짜에 맞춰 직접 확인해야 합니다. 여러 구간 또는 자정을 넘는 방문은 지원하지 않습니다.

비용은 0~500,000원의 정수입니다. 비워 두면 기존 추천 참고값을 사용하고, 명시적 0원은 입력값으로 반영합니다. 활동비는 1인당 금액에 여행 인원을 한 번만 곱합니다. 숙소 비교·장소 비교·여행 참고 예산에 같은 기준을 쓰며 실제 지출·결제·예약 상태를 바꾸지 않습니다.

저장은 현재 방문 시각을 바꾸지 않습니다. 불일치 조건도 저장하여 **전체 일정 비교**에서 해결할 수 있고, 두 방향 배치는 가능 시간 안에서 계산합니다. 고정 방문을 옮기거나 체류 시간을 줄여 해결하지 않습니다. 경로·교통 예약·숙소 경유 비교와 방문일정 복원도 공통 충돌 검사를 통과해야 합니다. 불가능하면 해당 안을 적용할 수 없습니다.

조건은 장소에 종속됩니다. 다른 후보로 변경하면 시간·비용·메모를 비웁니다. 같은 장소의 방문일정 복원에서는 최신 조건을 유지하며, 장소가 바뀌는 복원도 과거 조건을 재사용하지 않습니다. 조건 저장 자체는 방문일정 복원 이력을 추가하지 않으며, 변경/초기화는 이 양식에서 명시적으로 저장합니다. 버전은 증가하므로 공동 편집·열린 비교·경로 영수증은 최신 버전을 다시 확인해야 합니다.

## API와 저장

`PUT /api/trips/{id}/items/{itemId}/conditions`

```json
{"version":0,"startTime":"10:00","endTime":"17:00","cost":3000,"note":"방문 날짜의 운영 안내·성인 요금 확인"}
```

시간 두 값이 null/빈 문자열이면 시간 조건을 해제합니다. 한쪽만 입력할 수 없습니다. `cost:null`은 비용 초기화, `cost:0`은 0원 입력입니다. 메모는 500자 이내이며 빈 값으로 초기화합니다. 저장 응답은 최신 여행 상세입니다.

- 접근: 로그인·CSRF·수락한 동행 권한·해당 여행의 항목을 서버에서 검사합니다.
- 400: 시간/체류 범위, 소수·음수·초과 금액, 메모, 음수 버전 오류.
- 404: 해당 여행에 없는 항목. 409: 최신 여행 버전과 불일치.
- V7은 방문 항목에 `visitStart/visitEnd/visitCost/visitNote` 열을 추가합니다. 기존 데이터는 조건 미입력으로 유지됩니다.
- 상세의 `visitConditionIssues`와 공통 `schedule.issues`의 `VISIT_WINDOW`가 현재 불일치를 안내합니다.
- 공개 공유는 기존 화이트리스트를 유지하여 시간 조건·입력 비용·메모를 공개하지 않습니다.

`VisitConditions`는 검증·유효 비용·충돌 계산, `WholeSchedule`은 배치 범위, `BookingSchedule.inspect`는 모든 시간 변경의 공통 최종 검사를 맡습니다. 외부 API를 저장/비교 때 추가 호출하지 않습니다.
