# 초대·신고 운영·개인 휴지통의 처리 기준

## 여행 초대와 참여 변경

`POST /api/invitations`는 `tripId`, `email`을 필수로 받는다. 이메일 앞뒤 공백은 정리하고 형식·최대 길이를 검사한다. 비어 있는 이메일을 조회하거나 `trim()`하여 서버 오류로 처리하지 않는다. 기존처럼 여행 소유자만 초대할 수 있으며 현재 참여·대기 초대 중복과 양방향 차단을 검사한다. 개인 대화는 닉네임 검색을 사용하며 여행 초대의 이메일 입력과 구분한다.

`POST /api/invitations/{id}/respond`의 `accept`는 필수 불리언이다. 누락을 거절로 바꾸지 않으며 검증 실패 때 대기 초대는 유지된다. 수락은 현재 차단 상태를 다시 검사한다. 차단한 회원의 기존 초대를 거절하는 것은 참여 권한을 만들지 않으므로 허용한다.

초대 쓰기는 ID 순서로 정렬한 회원 행 → 여행 행 → 초대 변경 순서로 잠근다. 공유 일정 가져오기는 가져오는 회원 → 원본 여행 순서, 개인 대화의 차단 변경도 같은 회원 행을 사용한다. 초대에서 여행을 먼저 잡고 회원을 기다리면 같은 공유 원본의 가져오기와 서로 반대 행을 기다릴 수 있어 이 순서를 지킨다.

회원과 여행을 잠그기 전 조회는 소유권·수신자·초대 소속을 확인하는 예비 검사다. 잠금을 얻은 뒤 현재 소유자·초대 대기 상태·차단·참여 여부를 다시 검사한다. 이미 완료된 차단 뒤의 수락은 거절한다. 차단과 수락이 동시에 시작했다면 같은 회원 잠금을 먼저 얻은 요청을 기준으로 순서를 정하며, 차단은 이미 수락한 여행의 참여를 자동 해제하지 않는다.

`POST /api/trips/{id}/leave`, `POST /api/trips/{id}/members/{member}/remove`의 `version`도 필수 0 이상의 정수다. 빈 JSON을 버전 0으로 간주해 초기 여행의 참여를 변경하지 않는다. 현재 참여·소유권과 버전 충돌 검사는 기존 서비스가 수행한다.

## 관리자 신고 목록

운영 화면은 `GET /api/admin/reports/search`를 사용한다. 서버의 관리자 권한을 통과해야 하며 필터는 목록을 자르기 전에 DB에 적용한다.

| 값 | 기본값·범위 |
| --- | --- |
| `status` | `OPEN` 기본, `RESOLVED`, `ALL` |
| `page` | 1 기본, 1~1,000,000 |
| `pageSize` | 20 기본, 1~30 |
| 응답 | `items`, `total`, `page`, `pageSize`, `totalPages` |

정렬은 접수 시각 내림차순·ID 내림차순이다. 오래된 미처리 신고도 상태 필터와 페이지 이동으로 찾을 수 있다. 마지막 신고 처리로 페이지 수가 줄면 서버가 실제 마지막 페이지로 보정하고 화면의 주소도 교체한다. 필터·페이지는 URL로 유지한다.

신고 증거는 접수 당시 대상 한 건을 보존한 기존 계약을 따른다. 목록 확장이 다른 개인 대화의 열람 권한을 추가하지 않는다. 기존 `GET /api/admin/reports`의 최근 100건 배열은 이전 클라이언트 호환용으로 유지하며 새 운영 화면은 이 제한된 경로를 사용하지 않는다.

## 내 글 휴지통

휴지통 모달은 `GET /api/community/trash/search`로 현재 로그인 회원의 삭제 기록만 조회한다. `memberId` 같은 요청 값으로 다른 회원의 휴지통을 선택할 수 없다.

| 값 | 기본값·범위 |
| --- | --- |
| `page` | 1 기본, 1~1,000,000 |
| `pageSize` | 12 기본, 1~30 |
| 응답 | `items`, `total`, `page`, `pageSize`, `totalPages` |

항목은 `id`, `category`, `region`, `title`, `version`, `deletedAt`, `hidden`만 제공한다. 본문·댓글·이메일·작성자 ID는 포함하지 않는다. 정렬은 삭제 시각 내림차순·ID 내림차순이며 같은 시각의 기록도 ID로 순서를 고정한다. 모달 안에서 페이지를 이동하고 기존 복원 API로 선택한 글을 복원한다. 운영진 숨김과 작성자·버전 검사는 우회하지 않는다.

기존 `GET /api/community/trash`의 최근 100건 배열은 호환용으로 유지한다. 새 화면은 서버 페이지를 사용해 100개보다 오래된 글도 직접 찾고 복원할 수 있다. 페이지 번호는 열려 있는 모달 안에서만 유지하며 개인 삭제 기록을 공유 주소로 만들지 않는다.

## 계정 변경과 지연 응답

커뮤니티는 공개 경로이지만 글쓰기·신고·댓글 수정·내 휴지통 양식은 계정에 속한다. 경로와 회원 ID가 달라지면 화면 경계를 다시 만들어 이전 양식을 닫는다. 글 저장·복원 응답은 마운트 여부, 요청을 시작한 회원 ID, 브라우저의 실제 현재 경로를 확인한 뒤 후속 화면 이동을 수행한다. 지연 로딩으로 이전 화면이 잠시 남아 있는 경우에도 새 경로를 오래된 응답으로 덮지 않는다.

알림 읽음의 실패 복원은 같은 계정·마운트에서만 수행한다. 로그아웃이나 다른 계정 로그인 뒤 도착한 실패가 이전 회원의 알림 목록을 캐시에 다시 넣지 않는다. 같은 계정이 다른 화면으로 이동한 경우 읽음 동기화는 유지하되, 뒤늦게 완료된 알림 클릭이 현재 화면을 투표 화면으로 이동시키지 않도록 실제 경로를 검사한다.

서비스 설정 조회 중이거나 실패한 관리 화면은 확인 중·오류·재시도를 표시한다. 아직 읽지 못한 `sampleData` 값을 운영 데이터 설정 완료로 표시하지 않는다.
