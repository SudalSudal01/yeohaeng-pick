# 관광공사 이용정보 연결

장소 탐색 카드와 저장된 여행의 방문 카드에서 **운영시간·이용정보**를 연다. 관광공사 검색 결과의 주소·장소 종류를 보고 같은 장소를 직접 선택하면 이용 시간·쉬는 날·이용요금 원문을 볼 수 있다. 제공하지 않은 값은 미제공으로 표시하고 오류를 빈 정보나 무료 요금으로 대체하지 않는다. 관광공사 콘텐츠와 Kakao 장소 ID는 자동 병합하지 않는다.

## 키 등록

1. [한국관광공사_국문 관광정보 서비스_GW](https://www.data.go.kr/data/15101578/openapi.do)에서 활용 신청한다. 2026-10-12 공식 안내는 무료, 개발계정 트래픽 1,000, 개발단계 자동승인이다. 계정의 실제 승인 상태와 한도는 포털에서 확인한다.
2. 프로젝트 루트 `.env`에 `TOUR_API_KEY=발급받은키`를 추가한다. Encoding/Decoding 키를 지원하며 키를 `VITE_` 변수나 프론트 코드에 넣지 않는다. `.env`는 Git에서 제외한다. `.env.example`은 빈 입력 항목만 제공한다.
3. 선택적으로 `TOUR_API_DAILY_LIMIT=300`을 설정한다. 단일 서버에서 한국 날짜 기준 캐시 미적중 외부 요청을 기본 300회, 설정 시 1~1,000회로 제한한다. 서버 재시작 시 초기화되며 여러 서버/다른 앱/직접 호출의 공급자 한도와 공유되지 않는다. 공급자 오류 응답도 요청 횟수에 포함한다.
4. 여행픽 개발 서버를 종료하고 다시 실행한다. `/api/config`의 `tourismConfigured`만 공개하고 서비스키는 반환하지 않는다.

```powershell
.\scripts\Stop-Dev.ps1
.\scripts\Start-Dev.ps1
```

## 조회 범위와 출처

`KorService2/ldongCode2`에서 실제 법정동 지역 코드를 찾고 `searchKeyword2`에 keyword/lDongRegnCd, 강릉은 lDongSignguCd를 보낸다. 검색은 서울·부산·제주·강릉, 페이지당 20개·최대 50페이지다. 현재 명세에서 미사용/삭제 예정인 areaCode/sigunguCode/cat 필터와 예전 detailCommon 플래그는 사용하지 않는다. 전국 관광공사 데이터를 추천 후보에 통합하는 작업은 후속 범위다.

선택한 contentId로 `detailCommon2`를 조회한 뒤 서버가 응답에서 얻은 contentTypeId로 `detailIntro2`를 조회한다. 관광지(type 12)는 입장료가 반복정보에 있을 수 있어 `detailInfo2`를 추가 조회한다. 추가 안내는 최대 100개이며 응답이 일부인 경우 미제공으로 단정하지 않고 확인 오류를 안내한다. 다른 유형은 소개정보의 이용요금 필드만 표시한다. 숙소 객실 표의 비수기/성수기 금액을 실제 예약 가능한 가격으로 가져오지 않는다. 통신 주소는 서버에 고정돼 있으며 사용자가 임의 공급자 URL을 지정할 수 없다.

지역 코드는 24시간, 검색은 5분, 상세의 각 응답은 30분 캐시한다. 캐시는 최대 400개, 동시 외부 요청은 2개다. 표시하는 조회 시각은 상세 묶음에서 가장 오래된 조회 시각이며 공급자 modifiedtime은 별도로 보여준다. 원문 HTML은 텍스트로 변환하고 홈페이지 링크는 http(s) 주소만 분리한다. 사진은 가져오지 않는다.

요금 설명을 숫자로 자동 변환하거나 예산·경비·예약·방문 시각을 바꾸지 않는다. 운영 안내는 여행 날짜의 임시 휴무, 입장 마감, 현장 변경을 보장하지 않는다. 정보가 없거나 검색되지 않는 장소는 기존 지도 상세·리뷰 링크에서 확인한다. 공식 계약은 [공공데이터포털 활용명세](https://www.data.go.kr/data/15101578/openapi.do?recommendDataYn=Y)를 기준으로 확인했다.
