# 공개 일정 가져오기

공유 페이지의 **내 여행으로 가져오기**에서 로그인한 사용자가 새 날짜·출발지·인원·예산·이동수단·취향을 선택합니다. 원본의 지역과 일수, 방문 순서·시각을 유지하며 별도 소유 여행을 생성합니다. 가져온 뒤 기존 일정의 장소 대안·예약 기록·숙소 선택·동행 초대 기능을 사용할 수 있습니다.

## 공개와 복사의 범위

- 공유 응답: 제목·지역·원본 날짜·이동수단, 방문 장소의 공급자 ID/이름/분류/좌표/링크/실내 여부/출처/체류 시간/참고 활동비, 방문 일차·순서·시각, 공개 스냅샷 해시입니다. 참고 활동비는 기존 장소의 추정값이고 직접 확인 비용이나 결제 금액이 아닙니다.
- 제외: 원본 여행/항목 내부 ID·소유자·출발지·인원·예산·취향·예약·숙소·경비·준비물·동행·대화·이력·방문 가능 시간·직접 입력 비용/메모·고정 여부·조회 경로입니다. 새 항목 ID, 예약 전/NONE, 고정 해제, 직접 입력 조건 없음으로 생성합니다. 새 여행에는 운영시간/요금과 이동/숙소 재확인 준비물 두 개만 추가합니다.
- 원본 편집 권한과 멤버십은 부여하지 않습니다. 원본 삭제·토큰 재발급·공유 종료는 향후 가져오기를 막고 이미 생성한 독립 복사본에는 영향을 주지 않습니다. 공유를 만들기 전에 이 범위를 안내합니다.

## HTTP 계약과 원자성

`GET /api/share/{token}`은 익명 조회입니다. `POST /api/trips/import`는 로그인과 CSRF가 필요하며 `{token, snapshot, requestId, conditions}`를 받습니다. token/snapshot은 소문자 64자리 16진수, requestId는 소문자 UUID입니다. conditions는 기존 TripRequest 검증을 따르고 지역/여행 일수는 공개본과 같아야 하며 숙소 입력은 비워야 합니다. 응답은 `{id}`입니다. 장소·가격·예약·회원 ID는 클라이언트에서 받지 않습니다.

회원 행 잠금 → 동일 요청 완료 기록 확인 → 원본 여행 행 잠금 → 잠금 후 토큰 재검사 → 공개 해시 비교 → 새 여행/회원 연결/항목/준비물/완료 기록 삽입을 한 트랜잭션에 수행합니다. 공유 종료·재발급·삭제·공동 편집과 같은 여행 잠금을 사용하므로 먼저 완료한 작업을 기준으로 결과가 결정됩니다. 생성 중 실패는 전체 롤백합니다. 공개 조회도 짧은 여행 잠금으로 한 시점의 공개 내용을 반환합니다.

공개 필드만 SHA-256으로 해시하므로 비공개 경비나 예약 변경만으로 가져오기를 막지 않습니다. 사용자가 본 공개 내용이 달라졌으면 409로 거절합니다. 화면은 최신 내용을 조회하고 변경된 방문 목록을 양식 안에서 보여 줍니다. 내 입력 조건은 유지하며 명시적인 재실행으로 새 공개본을 가져옵니다. 종료/재발급/삭제 링크는 404, 유효하지 않은 조건은 400입니다.

## 중복 방지와 보존

V14 `trip_imports`는 회원+요청 UUID, 복사본 ID, 요청 내용 해시, 최초 시각만 보존합니다. 원본 ID·공유 토큰·조건 원문은 보존하지 않습니다. 같은 회원·키·본문의 재전송은 기존 결과를 반환하고 다른 본문은 409입니다. 복사본을 삭제하면 FK가 NULL로 바뀌며 같은 요청으로 되살리지 않고 410을 반환합니다. 다른 회원이 같은 UUID를 사용해도 서로의 결과에 접근하지 못합니다. 탈퇴 시 해당 회원의 완료 기록을 삭제합니다. 각 테이블/컬럼에는 실제 한국어 DB 코멘트를 추가합니다.

응답을 잃었을 때 화면은 같은 키와 본문을 재사용하고 조건 변경을 잠급니다. 같은 페이지에서 창을 닫았다 다시 열어도 메모리의 요청을 유지합니다. 페이지 새로고침/다른 페이지 이동/계정 변경 후에는 새 가져오기로 취급하며 브라우저 저장소에 출발지나 요청을 영구 저장하지 않습니다. 이미 완료된 동일 요청의 결과는 공유 종료 후에도 반환할 수 있지만 복사본의 현재 참여 권한을 다시 검사합니다.

새 날짜의 운영시간·휴무·재고·요금·교통 경로를 자동 재검증하거나 최적화하지 않습니다. 외부 API/AI를 다시 호출하지 않고 공개 당시 장소와 참고 추정값을 복사합니다. 무료/유료 확정 또는 예약 성공으로 표시하지 않습니다. 대규모 공개 조회 잠금 경합, 운영 보존 기간·백업 만료 정책은 후속 검증이 필요합니다.
