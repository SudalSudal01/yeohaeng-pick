# 커뮤니티 글·댓글 관리

로그인한 작성자는 상세의 **내 이야기 관리**에서 제목·본문·지역과 동행 모집 날짜/인원을 수정합니다. 이야기 종류는 등록 후 유지해 기존 댓글·모집 대화의 맥락을 지킵니다. 수정은 모집 마감/취소 상태를 바꾸지 않으며 모집 상태는 별도 버튼으로 변경합니다. 본문은 HTML 실행 없이 텍스트로 표시합니다.

## 삭제와 복원

- 삭제 확인에서 공개 제외·댓글 보존·모집 마감·개인 대화/여행 참여 유지 범위를 안내합니다.
- 삭제는 `deleted_at`을 기록하는 휴지통 이동입니다. 공개 목록·상세와 새 댓글 등록에서 제외합니다. 댓글과 신고 대상 참조, 기존 개인 대화, 별도 여행 참여는 유지합니다.
- 커뮤니티의 **내 글 휴지통**은 작성자 본인이 삭제한 최근 100개만 표시합니다. 목록에 본문/댓글을 내려보내지 않습니다. 자동 영구 삭제나 보관 기한은 설정하지 않았습니다.
- 복원하면 본문과 기존 댓글이 다시 공개됩니다. 동행 모집은 **CLOSED(마감)** 상태로 돌아오고 작성자가 ‘다시 모집하기’를 눌러야 열립니다.
- 운영진 숨김(`hidden`)은 작성자 삭제와 별개입니다. 숨긴 글의 작성자 수정·상태 변경·복원으로 공개를 되살릴 수 없습니다. 휴지통에서도 숨김 상태의 복원 버튼을 비활성화합니다.
- 신고 당시 본문은 V13부터 별도 보존합니다. [신고 증거와 처리](report-evidence.md). 글 영구 삭제, 보존 기간 정책과 전체 목록 페이지네이션은 후속입니다.

## 내 댓글 수정·삭제

댓글 작성자만 **댓글 수정/댓글 삭제** 도구를 사용합니다. 게시글 작성자에게 타인의 댓글 관리 권한을 부여하지 않습니다. 수정창은 2,000자 제한·공백 검사·작성 시각/수정 표시를 제공하고, 삭제 확인창에서 대상 본문과 직접 복원할 수 없음을 안내합니다.

댓글 삭제는 V9의 `deleted_at`으로 공개 제외하며 내부 행은 보존합니다. 공개 상세에는 삭제 댓글의 ID·본문·작성자를 모두 내려보내지 않고 댓글 수도 공개 댓글만 셉니다. 댓글 복원 API/휴지통은 없으며 부모 글을 복원해도 삭제 댓글은 돌아오지 않습니다. 삭제된 글/운영진이 숨긴 글의 댓글 변경은 404입니다. 향후 비공개 글에 남긴 본인 댓글 일괄 관리·보존 기간 정책은 별도 작업입니다.

`CommunityCommentService`는 부모 게시글 행을 먼저 잠근 뒤 댓글 소속·공개 여부·댓글 작성자·댓글 버전을 확인합니다. 글 삭제/숨김과 댓글 변경이 같은 잠금 순서를 사용합니다. 각 댓글의 version은 독립적이며 다른 댓글이나 부모 글 변경으로 증가하지 않습니다. 같은 댓글의 동시 수정은 하나만 성공(200/409)하고, 수정/삭제 경합은 한 작업만 성공하며 나머지는 409 또는 삭제 후 404입니다.

열린 관리창은 처음 버전과 초안을 유지합니다. 상세의 15초 재조회 또는 서버 409로 변화를 감지하면 저장/삭제 실행을 막고 명시적으로 최신 댓글을 불러오게 합니다. 최신 조회가 실패해도 충돌 상태를 유지합니다. 다른 창에서 삭제하면 초안 복사 안내와 닫기만 제공하고 실행 버튼을 없앱니다. 일시적인 통신 오류는 초안을 지우지 않습니다.

## API

모두 `/api` 기준입니다. 작성·수정·삭제·복원·댓글·모집 변경은 세션과 CSRF를 검사합니다. 휴지통 GET은 공개 커뮤니티 조회 예외보다 먼저 인증을 요구합니다.

| 요청 | 본문/반환 |
| --- | --- |
| POST /community/posts | 기존 `{category,region,title,body,recruitmentDate?,capacity?}` → 상세 |
| PUT /community/posts/{id} | `{version,content:{...작성 내용}}` → 최신 상세 |
| DELETE /community/posts/{id} | `{version}` → 성공 200 빈 본문 |
| GET /community/trash | 본인 휴지통 `{id,category,region,title,version,deletedAt,hidden}[]` |
| POST /community/posts/{id}/restore | `{version}` → 복원 상세 |
| PUT /community/posts/{id}/status | `{version,status:OPEN|CLOSED|CANCELLED}` → 최신 상세 |
| POST /community/posts/{id}/comments | `{body}` → 최신 상세 |
| PUT /community/posts/{id}/comments/{commentId} | `{version,body}` → 성공 200 빈 본문 |
| DELETE /community/posts/{id}/comments/{commentId} | `{version}` → 성공 200 빈 본문 |

상세에 `version`과 선택적 `updatedAt`을 추가합니다. 모집 날짜는 시간대가 없는 `yyyy-MM-dd`로 반환합니다. 댓글 등록은 본문 버전을 증가시키지 않습니다. 제목 120자, 본문 10,000자, 지역 50자, 댓글 2,000자, 동행 모집 1~20명과 날짜 필수 조건을 서버에서도 검사합니다. 일반 글의 모집 조건은 저장하지 않습니다.

권한 부족 403, 없는/삭제된/숨긴 공개 글 404, 오래된 버전·복원 상태 충돌 409, 잘못된 중첩 입력 400입니다. DTO의 version/content는 누락을 허용하지 않습니다.

## 저장과 화면 동기화

`CommunityPostService`가 게시글 행 잠금 → 현재 작성자/공개 여부 → 요청 버전 → 조건부 SQL 변경을 하나의 트랜잭션에서 처리합니다. 수정·삭제·복원·모집 상태·댓글 등록·운영진 숨김은 같은 행을 잠급니다. 먼저 완료한 댓글은 보존되고 삭제 완료 후 댓글 등록은 거절합니다. 두 창의 같은 버전 수정은 하나만 성공합니다. 운영 PostgreSQL에서의 잠금 검증은 별도로 필요합니다.

V8은 기존 글에 version=0을 추가하고 수정/삭제 시각을 미입력으로 둡니다. V1~V7을 수정하지 않으며 기존 본문·댓글·모집 상태를 변경하지 않습니다.

V9는 기존 댓글에 version=0, nullable updated_at/deleted_at만 추가합니다. 작성 시각과 본문은 유지하고 V1~V8은 수정하지 않습니다. 공개 댓글 계약은 `{id,authorId,nickname,body,createdAt,updatedAt?,version}`입니다.

상세·목록은 15초 간격으로 재조회합니다. 수정 창은 열린 버전을 유지하고 변화가 감지되면 저장을 막습니다. 작성 중인 내용을 자동 덮어쓰지 않고 복사 안내 후 명시적으로 최신 글을 불러오게 합니다. 일시적인 상세 조회 실패는 기존 글과 수정 초안을 유지하고 오류를 안내합니다. 삭제/숨김 404는 편집창을 닫고 공개 제외 안내로 전환합니다. 이미 내려받은 자료를 소급 회수하거나 비활성/오프라인 탭에 즉시 전달하는 실시간 푸시는 아닙니다.

목록·상세는 별도 모듈로 지연 로드하며 로딩과 파일 로드 실패 후 다시 열기 화면을 제공합니다. 모바일 입력은 16px, 안내/버튼 14px 이상, 주요 버튼 48px 이상입니다. 안내와 실행 영역을 24px 이상 분리하고 작은 화면은 세로 배치·모달 내부 스크롤을 사용합니다.
