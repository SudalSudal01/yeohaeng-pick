# 김명현 백엔드 포트폴리오

지원용 PDF와 상시 공개 가능한 정적 웹을 함께 관리합니다. 순서는 **제때약 → 여행픽 → 5ASIS**이며, `content.json`을 두 형식의 공통 원본으로 사용합니다.

프로젝트 상세 모달은 화면 8장을 선택 버튼으로 전환하고 원본 크기로 열 수 있습니다. 제때약은 원본 React와 가상 API 응답, 여행픽은 로컬 시연·QA, 5ASIS는 원본 JSP·CSS의 로컬 재현 화면입니다. 촬영 방식은 `mediaNote`, 각 화면 설명은 `media`에서 관리합니다. PDF는 대표 화면을 프로젝트 설명과 함께 배치한 10쪽입니다.

## 파일

첫 화면은 인사말과 프로필, 프로젝트 바로가기로 구성합니다. 한 문장으로 전달할 내용은 줄을 유지하고, 역할·이유·검증처럼 전환되는 지점에 문단 간격을 둡니다. 프로젝트 상세에서는 맡은 역할 바로 뒤에 사용한 기술과 이유를 배치하고, 이어서 화면과 확인한 동작을 보여줍니다. 웹과 PDF는 `content.json`에서 같은 문안을 읽습니다.

웹의 ‘AI 활용’과 PDF 2쪽은 Gemini를 서비스에 사용한 이유와 Codex를 개발에 활용한 판단을 소개합니다. Oracle 전환은 직접 정한 요구와 검증 기준을 짧은 단계로 보여줍니다. 실제 추천 코드와 Oracle 이전 기록은 해당 시점의 여행픽 커밋에 연결합니다.

웹에서는 화면에 들어오는 카드, 상세창, 갤러리에 짧은 전환을 사용합니다. 기기의 동작 줄이기 설정에서는 전환을 끄고 즉시 내용을 표시합니다.

- `../output/pdf/kim-myeonghyeon-portfolio.pdf`: 회사 지원에 첨부할 10쪽 PDF.
- `site/`: 웹 배포 폴더. 서버·DB·API 키 없이 HTML/CSS/JavaScript만 제공합니다.
- `../output/web/kim-myeonghyeon-portfolio-web.zip`: 정적 호스팅에 올릴 웹 파일 묶음. 압축을 풀면 `index.html`이 바로 루트에 있습니다.
- `content.json`: 공개를 허용한 프로필과 프로젝트 설명. 연락처는 사용자가 지정한 값입니다.
- `build.py`: PDF 생성, 웹 JSON 동기화, 웹 다운로드용 PDF 복사.
- `evidence.md`: 코드 근거·기여도·검증 기록의 출처와 한계.

## 로컬 미리보기

프로젝트 루트에서 실행합니다. Python이 설치된 PC에서 사용할 수 있습니다.

```powershell
python -m http.server 5200 --bind 127.0.0.1 --directory portfolio/site
```

브라우저에서 `http://127.0.0.1:5200`을 엽니다. `index.html`을 파일로 바로 열면 브라우저의 로컬 JSON 접근 제한 때문에 내용을 읽지 못할 수 있으므로 HTTP 미리보기를 사용합니다.

## PDF 재생성

Python의 `reportlab`이 필요하며 현재 작성 스크립트는 Windows의 맑은 고딕을 포함합니다. 다른 OS에서는 `build.py`의 글꼴 경로를 해당 PC의 한국어 TrueType 글꼴로 변경합니다.

```powershell
python portfolio/build.py
```

생성 후 모든 페이지를 PNG로 렌더해 글자 누락·겹침·하단 잘림을 확인합니다. 사이트와 PDF에 연락처·담당 기능·검증 수가 같은지 함께 확인합니다. 근거 없는 역할·성능 수치·운영 배포 주장은 추가하지 않습니다.

## 상시 공개

2026.10.13 배포 완료: **https://sudalsudal01.github.io/backend-portfolio/**

공개 저장소는 https://github.com/SudalSudal01/backend-portfolio 이며 `main` 루트를 GitHub Pages로 배포합니다. 여행픽 저장소의 이력은 복제하지 않고 `site/`의 공개용 파일만 게시했습니다. 사진·연락처·PDF·JSON의 공개 접속을 확인했습니다. PC나 로컬 서버를 꺼도 GitHub Pages에서 제공됩니다. 여행픽 소스 저장소도 사용자 요청으로 공개 전환했으며 포트폴리오와 PDF의 코드 링크에서 로그인 없이 확인할 수 있습니다.

수정할 때는 이 프로젝트에서 콘텐츠와 PDF를 검증한 뒤, 공개 저장소의 정적 파일을 갱신하고 커밋·푸시합니다. 두 저장소 간 동기화는 현재 수동이며, 여행픽 저장소의 푸시만으로 공개 페이지가 갱신되지는 않습니다.

Git은 코드 관리이고 호스팅은 웹 주소를 제공하는 서비스입니다. 정적 포트폴리오를 배포하는 데 여행픽 API·Oracle 서버를 계속 켜 둘 필요가 없습니다. 현재 `5200` 주소는 이 PC에서만 보는 로컬 미리보기이며 공개 주소가 아닙니다.

현재 방식은 **포트폴리오 전용 공개 저장소 + GitHub Pages**입니다. 여행픽 소스와 포트폴리오 배포 파일을 별도 저장소로 관리하며 `site/`의 공개용 파일만 포트폴리오 저장소 루트로 복사합니다. `Settings → Pages → Deploy from a branch → main / root`로 배포합니다.

GitHub Free의 Pages는 공개 저장소를 기준으로 제공되며 비공개 저장소의 Pages는 유료 플랜 범위입니다. 웹 소스까지 비공개로 유지하고 싶다면 개인 비공개 저장소를 Vercel 또는 Cloudflare Pages에 연결하는 방법을 검토할 수 있습니다. Vercel Hobby에는 개인/조직 저장소와 커밋 작성자 관련 제한이 있으므로 계정·저장소 형태를 확인합니다.

처음 배포할 때 GitHub/호스팅 계정 연결과 공개 범위를 확인합니다. 소스에는 `.env`, DB 덤프, 실사용자 화면, 다른 팀원의 연락처를 포함하지 않습니다. 이 포트폴리오에는 본인이 공개용으로 지정한 이름·직무·전화번호·이메일·프로필 사진을 포함했습니다.

공개 주소는 호스팅이 유지되는 동안 접속할 수 있습니다. Git에 변경을 푸시하면 자동 배포하도록 연결할 수 있고, 개인 도메인은 선택 사항입니다. 백엔드 서비스 자체를 배포하는 일은 정적 포트폴리오 배포와 별도입니다.

## 소개·기술·교육 구성

사용자가 설명한 개발 계기, 학과 개편, 청주 소재 SI 기업 실습과 휴먼교육센터 수료를 소개에 담았습니다. 기술은 실제 프로젝트 적용 분야로 분류합니다. 학력·교육·자격과 팀 개발 기간·인원은 본인 확인을 기준으로 표시합니다.

웹 메뉴는 데스크톱에서 상단에 유지하고 모바일에서는 메뉴 버튼으로 접습니다. 여행픽은 기존 로컬 시연·QA 캡처, 제때약은 원본 React를 실행하고 가상 API 응답을 사용한 캡처, 5ASIS는 원본 JSP·CSS를 로컬 HTML로 재현한 캡처입니다. 촬영 방식을 설명에 유지하며 실제 서버 검증 결과와 혼용하지 않습니다. PDF는 소개·교육과 기술 경험을 포함한 10쪽입니다.

## 요약 카드와 상세 모달

소개 영역에 학력·교육·자격을 함께 올리고, 기술과 프로젝트는 요약 카드로 구성합니다. 프로젝트는 세 카드만 먼저 보여 주며 상세 화면·역할·처리 흐름·문제 해결·검증 기록은 스크롤 가능한 모달에서 확인합니다. 모달은 배경 스크롤을 잠그고 Tab 포커스를 내부에서 순환합니다. Escape·닫기 버튼·배경 클릭으로 닫을 수 있고 원래 카드로 포커스를 돌립니다. 기술 상세의 관련 프로젝트는 모달을 중첩하지 않고 내용을 교체합니다.
